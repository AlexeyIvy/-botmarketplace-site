## 4. Why lowering gates is not the preferred repair

The 2-second causal-as-of rule already discards stale observations.

Lowering the 0.98, 1000ms or 5s gates after observing the result would be a post-hoc rescue of the clock architecture.

More importantly, carrying old transaction prices across inactive seconds can create false cross-venue price differences.

Therefore the next clock representation should remove carry-forward rather than relax stale-data criteria.

## 5. New engineering hypothesis

Use a strict event-binned representation:

`STRICT_COACTIVE_1S`

For each UTC second:

- aggregate/identify only trades whose event timestamps fall inside that exact second;
- a venue is active only if it has >=1 trade inside the second;
- a cross-venue synchronized second exists only when **both** venues are active in that same UTC second;
- no last-trade carry-forward;
- no future interpolation;
- no price comparison during clock qualification.

This representation reduces stale-price artifacts and is less dependent on rare quiet-period gaps.
